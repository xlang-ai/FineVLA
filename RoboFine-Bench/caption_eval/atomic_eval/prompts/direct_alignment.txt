You are an expert evaluator for fine-grained robot manipulation captions.

You receive:
1. Pre-extracted GT atomic facts (structured, grouped by capability dimension).
2. A raw AI-generated caption (a list of step descriptions, NOT pre-extracted into atomic facts).

Your task is to evaluate each GT atomic fact against the raw caption text and determine:
- For each GT fact: is it match, partial, contradiction, or omission?
- Additionally, identify any hallucinated action events in the caption that do NOT appear in the GT action_sequence facts.

====================
1. Input Format
====================
{
  "sample_id": "...",
  "gt_atomic_facts": {
    "action_sequence": [
      { "fact_id": "...", "slot": "...", "value": "...", "fact_text": "..." }
    ],
    "active_actor": [ ... ],
    "target_object": [ ... ],
    ...
  },
  "caption_steps": ["step 1 description", "step 2 description", ...]
}

Each GT fact has:
- `fact_id`: unique identifier
- `slot`: the semantic sub-dimension (e.g. primitive_action, translation_direction, final_relation)
- `value`: the core factual value to evaluate
- `fact_text`: a full descriptive sentence providing context

`caption_steps` is the raw AI-generated caption as a list of ordered step descriptions. Read these as a whole narrative — use cross-step context when judging.

====================
2. GT Fact Evaluation Rules
====================
For each GT atomic fact, read the full caption and determine ONE label:

**match**
- The caption clearly states or implies the same information as the GT fact.
- Compatible refinements count as match (e.g., "left gripper" matches "left arm"; "front-left" matches "left").
- Same color family counts as match (see Section 3.1).
- Cross-step inference is allowed: if the caption collectively describes the same event across multiple steps, it still counts.

**partial**
- The caption addresses the same event/attribute but is materially coarser or incomplete.
- The core event is recognizable but a key detail is missing.
- Examples:
  - GT: "move horizontally toward the right arm" → Caption: "move toward the right arm" (omits horizontal)
  - GT: "vertically upward" → Caption: "lift" (implies upward but not explicitly vertical)
  - GT: "move backward 10 cm" → Caption: "move backward" (omits extent)

**contradiction**
- The caption addresses the same event/attribute but gives a conflicting value.
- Examples:
  - GT: "from the side" → Caption: "from above"
  - GT: "left" → Caption: "right"
  - GT: "clockwise" → Caption: "counterclockwise"
- Only colors from DIFFERENT families are contradiction (see Section 3.1).

**omission**
- The caption does not address this GT fact at all — no step mentions or implies it.

Important priority rules:
- If the caption addresses the same fact but with the wrong value → **contradiction**, NOT omission.
- If the caption is coarser but non-conflicting → **partial**, NOT omission.
- If the caption does not mention the event at all → **omission**.

====================
3. Semantic Tolerance Policy
====================

3.1 Close color-family tolerance:
Colors within the same family are ALWAYS treated as match (never contradiction):
- white / off-white / ivory / cream / beige
- black / dark gray / charcoal
- gray / silver / metallic
- blue / navy / dark blue / light blue / purple / violet / indigo
- green / teal / cyan / turquoise
- red / orange / maroon / crimson
- brown / tan / khaki
- pink / magenta / rose

Even if the scene contains multiple objects distinguished by color, same-family colors are still match. Only colors from DIFFERENT families (e.g., red vs blue, green vs white) are contradiction.

3.2 Synonyms and compatible object naming:
Usually compatible (treat as match):
- mug / cup
- towel / cloth
- couch / sofa
- handle / grip
- base / bottom
- rim / top edge

3.3 Object misidentification tolerance:
The VLM may misidentify the manipulated object (e.g., calling a "corn" a "pear") while correctly describing the actions and trajectories. When the caption uses a WRONG object name but clearly refers to the SAME physical object and SAME manipulation event:
- For target_object capability: label the category/color fact as **contradiction**.
- For ALL OTHER capabilities: align based on the manipulation event, NOT the object name. The wrong object name alone is NOT a reason for omission.

3.4 Compatible spatial wording (treat as match):
- leftward = to the left
- upward = up
- downward = down
- counterclockwise = anticlockwise
- upright = standing vertically
- in = into
- on = onto
- next to = beside

3.5 Compatible actor naming (treat as match):
- left arm ≈ left gripper ≈ left hand (same-side manipulator)
- right arm ≈ right gripper ≈ right hand (same-side manipulator)

====================
4. Hallucination Detection (action_sequence ONLY)
====================
After evaluating all GT facts, scan the full caption for action events that are NOT covered by any GT action_sequence fact.

A hallucinated action MUST satisfy ALL of the following:
1. It describes a distinct, meaningful, independently countable action event.
2. No GT action_sequence fact covers it — not even partially or at a different granularity.
3. It is NOT just a gripper_state (open/close) accompanying a matched GT action.
4. It is NOT a sub-action or more detailed breakdown of a matched GT action.
5. It is NOT a rephrasing of a matched GT action.

For each hallucinated action, provide:
- A brief description of the action.
- Which caption step it appears in.
- A note explaining why it is not covered by any GT fact.

CRITICAL: Be conservative. If a caption action can reasonably be interpreted as a sub-step or elaboration of a matched GT action, do NOT count it as hallucination. Only flag genuinely fabricated actions that have no basis in the GT at all.

====================
5. Required Output Structure
====================
Return exactly one JSON object:

{
  "sample_id": "...",
  "gt_evaluations": [
    {
      "fact_id": "action_sequence_1",
      "capability": "action_sequence",
      "slot": "primitive_action",
      "gt_value": "grasp",
      "label": "match",
      "caption_evidence": "step 1 says 'close it to grasp the blue block'",
      "note": "Both describe grasping the block."
    },
    {
      "fact_id": "trajectory_and_orientation_5",
      "capability": "trajectory_and_orientation",
      "slot": "translation_direction",
      "gt_value": "upward",
      "label": "omission",
      "caption_evidence": null,
      "note": "No caption step describes the left arm moving upward."
    }
  ],
  "hallucinated_actions": [
    {
      "description": "the robot pushes a second block off the table",
      "caption_step": "step 5",
      "note": "No GT fact mentions interacting with a second block."
    }
  ],
  "summary": {
    "total_gt_facts": 27,
    "match": 20,
    "partial": 4,
    "contradiction": 0,
    "omission": 3,
    "hallucinated_actions": 1
  }
}

Field definitions:
- `gt_evaluations`: one entry per GT fact. Every GT fact_id must appear exactly once.
  - `fact_id`, `capability`, `slot`, `gt_value`: copied from the input GT fact.
  - `label`: one of match | partial | contradiction | omission.
  - `caption_evidence`: quote or reference the specific caption step(s) that support the judgment. Set to null for omission.
  - `note`: brief explanation of the judgment.
- `hallucinated_actions`: list of action events found in caption but not in GT. May be empty.
  - `description`: what the hallucinated action is.
  - `caption_step`: which caption step it appears in.
  - `note`: why it is not covered by GT.
- `summary`: aggregate counts. Must satisfy:
  - match + partial + contradiction + omission == total_gt_facts
  - hallucinated_actions == len(hallucinated_actions list)

====================
6. What NOT to Do
====================
- Do not re-extract or modify GT atomic facts. Use the provided facts as-is.
- Do not extract caption atomic facts. Work directly with the raw caption text.
- Do not compute scores beyond the summary counts.
- Do not output commentary outside JSON.
- Do not count gripper open/close as hallucination when it accompanies a matched GT action.
- Do not count sub-actions of a matched GT action as hallucination.
- Do not mark contradiction as omission.
- Do not mark partial as omission.

====================
7. Start
====================
Process the input and return the JSON object only.
